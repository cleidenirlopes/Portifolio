Entenda LLMs

A practical guide to Large Language Models — how they work and the vocabulary to talk about them with confidence

Every AI product — chatbots, copilots, agents — is a Large Language Model wrapped in instructions, tools and data. This guide breaks down the core concepts behind every LLM-powered system in plain language: what each term means, why it matters, and the one-breath version you can use to explain it to anyone.

The Core Concepts

What each term means, why it matters, and how to explain it in one breath.

Large Language Model (LLM)

What it is

A neural network trained on massive amounts of text to predict the next token. Given a sequence of words, it generates the most plausible continuation — which, at scale, produces reasoning, translation, summarization and code.

Why it matters

Every AI product — chatbots, agents, copilots — is an LLM wrapped in instructions, tools and data. Understanding the prediction-at-core model explains both its power and its failure modes.

Say it: "An LLM is a pattern-completion engine trained on text — it predicts the next token, and everything we build on top (agents, RAG, tools) is about steering that prediction with the right context."

Tokens & Context Window

What it is

Models don't read words — they read tokens (chunks of ~4 characters). The context window is the model's working memory: the maximum number of tokens (input + output) it can consider at once.

Why it matters

Tokens are how APIs charge, how limits are enforced, and why long documents don't "fit". Context windows define what you can put in a single prompt vs. what needs retrieval (RAG).

Say it: "A token is the unit of text an LLM reads and bills. The context window is its short-term memory — when knowledge doesn't fit, we don't retrain the model, we retrieve just the right pieces."

Temperature & Sampling

What it is

The model picks each next token from a probability distribution. Temperature controls how adventurous that pick is: low (0–0.3) = deterministic and consistent; high (0.8–1.2) = creative and varied.

Why it matters

It's a production decision, not a detail: a data-extraction bot needs temperature near 0 for reliability; a brainstorming assistant wants it higher. Knowing this separates intentional design from guesswork.

Say it: "Temperature tunes the trade-off between consistency and creativity — I set it near zero for anything that must be repeatable, like classification or extraction."

System Prompt vs. User Prompt

What it is

The system prompt sets the model's persistent role, rules and boundaries for the whole conversation. The user prompt is the individual request. A conversation is an ordered list of messages of these types.

Why it matters

The system prompt is where product behavior lives: tone, safety rules, output format. It's the difference between "using ChatGPT" and engineering a consistent AI product.

Say it: "The system prompt is the job description; the user prompt is the daily task. Product behavior is engineered in the system prompt, not hoped for in the user prompt."

Anatomy of an LLM API Call

What it is

An HTTPS request to a provider endpoint with: the model name, a list of messages (role + content), and parameters like temperature and max_tokens. The response returns generated text plus usage (input/output tokens) — the basis of cost.

Why it matters

This single request/response pattern is the building block of every module in this curriculum — n8n flows, RAG chains and agent frameworks all reduce to it. Cost = tokens × price per token.

Say it: "An LLM API call is just: send a model + a list of messages + settings, get text and a token bill back. Everything more complex is orchestration around this loop."

Function Calling & Structured Outputs

What it is

You describe functions (name, parameters, purpose) to the model; it decides when to "call" one and returns structured JSON — your code executes the real action (query a database, send an email). Structured outputs force the reply to match a strict schema.

Why it matters

This is the bridge between language and action — the mechanism that turns a chatbot into an agent. It's how LLMs touch real systems reliably instead of printing suggestions.

Say it: "Function calling lets the model choose the tool and fill in the arguments, but my code stays in control of execution — that's what makes an LLM safe to connect to real operations."

Hallucination & Grounding

What it is

A hallucination is a confident but false answer — a natural side effect of a next-token predictor that optimizes plausibility, not truth. Grounding means anchoring answers in provided sources: retrieved documents, databases, tool results.

Why it matters

In Trust & Safety terms: ungrounded output is unverified output. Mitigation is layered — grounding (RAG), structured validation, human review, and evals that measure factuality.

Say it: "An LLM optimizes for plausible text, not verified truth — so production systems ground it in retrieved sources and keep a human in the loop for anything consequential."

Where This Leads: RAG, Agents & MCP

What it is

RAG retrieves relevant documents and injects them into the context window (grounding at scale). Agents add function calling + loops + memory, so the LLM plans and acts across steps. MCP is the open standard that connects agents to tools and data sources uniformly.

Why it matters

These are the three pillars of the next phases of this curriculum — each gets a dedicated project, from a RAG knowledge base to a multi-agent team and an MCP server.

Say it: "RAG solves knowledge, function calling solves action, agent loops solve multi-step tasks, and MCP standardizes the connections — that's the whole architecture of modern AI systems."
